# 쉼, 자리 검증 기록

검증일: 2026년 11월 15일. APK: `apk/shimjari_release.apk`, 패키지 `io.shimjari.rest`, 버전 1.3.1(5).

## 빌드와 자동 검사

- JDK 18.0.2.1에서 Java 17 대상으로 빌드, Gradle 8.9, Android Gradle Plugin 8.7.3.
- compile/target SDK 35, Build Tools 35.0.0, 최소 API 28.
- `testReleaseUnitTest lintRelease assembleRelease` 성공.
- 단위 테스트 **53개 통과**, 실패 0, 오류 0.
- Android Lint: **오류 0, 경고 6**. 즉시 저장을 위한 SharedPreferences 동기 기록 제안 4건, 사용자 확인 후 인증서 전체 지문을 고정하는 CustomX509TrustManager 경고 1건, 공개 미디어 브라우저 서비스의 export 경고 1건이다. 초기 인증서 탐색에는 자격증명을 보내지 않으며 이후 요청은 전체 SHA-256 지문 일치를 요구한다. 미디어 브라우저는 표준 차량 호스트의 바인딩을 받아야 하므로 공개하며 루트 요청의 package/UID 일치를 검사하고 공개 음악 메타데이터만 제공한다. FGS 제어 서비스와 알람 수신자는 비공개다. 백업은 `allowBackup=false`, `fullBackupContent=false` 및 Android 12 이상 추출 제외 규칙으로 비활성화했다.
- 제출용 RSA 2048비트 키로 서명했으며 `apksigner verify --verbose`에서 APK Signature Scheme v2 검증에 성공했다. 서명 키·비밀번호는 공개 저장소에 포함하지 않는다.
- APK SHA-256은 [SHA256SUMS.txt](../apk/SHA256SUMS.txt)에 기록했다.

테스트 범위는 정차 상태 불명·주행·NaN의 차단, 읽기 전용/미지원 공조, 원래 설정 누락, 잘못된 센서값과 범위, 사용자 변경 후 복원 제한, 시계 변경·재부팅·만료 시 타이머 계산, 3시간 상한과 프로필 스냅샷이다.

1.1의 추가 테스트는 장르 선호 우선, 날씨만으로 감정을 추정하지 않음, 수면 목적의 음악 무드, 시간·날씨에 따른 곡 순서 변화, 입력 목록 보존, BPM 누락, 공개 스트리밍 접근 제한, 잘못된 곡 ID, 음악 목록의 세션 복사와 미지원 날씨 코드 처리다.

1.2의 추가 테스트 7개는 이동 중 동승자 시작, 알려진 주행 상태에서 운전자 시작 차단, 상태 불명일 때 명시적 주차 확인, 좌석 역할 제한, 모드 변경·세션 복사, 구버전 모드 복구, 모드별 배경 재생 구분이다.

공식 Pleos Connect 2.1.0 x86_64 이미지의 Android 14(API 34) 에뮬레이터에 서명된 APK를 설치하고 실행했다. 물리 화면은 2560×1440, 160dpi이며 Pleos의 앱 창 1682×1210에서도 확인했다. 개인 차량이나 사용자의 실제 휴대전화에는 설치하지 않았다.

## 1.1 음악 연동 검증

- Open-Meteo에서 선택한 부산의 모델 예보를 실제 조회해 온도·시각·출처를 표시했다. 이후 사용자가 날씨를 직접 수정할 수 있음을 확인했다.
- Audius의 실제 검색 결과에서 공개 재생 가능 곡 5개를 표시하고, 곡명·아티스트·장르·무드·길이를 확인했다.
- 실제 스트리밍 재생 시 Android `MediaSession`에서 `PLAYING(3)` 상태와 현재 곡·아티스트 메타데이터를 확인했다. 단순 요청 성공 표시만으로 재생 성공을 판단하지 않았다.
- 일시정지는 `PAUSED(2)`, 다시 재생은 `PLAYING(3)`, 다음 곡은 메타데이터 변경으로 확인했다.
- 다른 앱으로 화면을 바꿔 쉼, 자리 화면이 숨겨졌을 때 `STOPPED(1)`과 `active=false`를 확인했다. Pleos의 홈 버튼만 누른 경우 앱 창이 계속 보일 수 있어 실제 화면 이탈과 구분했다.
- 프로세스 강제 종료·재실행 후 선택한 음악 목록이 유지되는 것을 확인했다.
- 최종 연속 검증 통과: 지역 예보 조회 → 기분·날씨·장르 선택 → 실제 곡 검색 → 곡 선택 → 재생 → 일시정지 → 다시 재생 → 다음 곡 → 다른 앱으로 전환해 중지 → 복귀 후 재생 → 종료·평가 → 프로세스 종료·재실행 후 음악 목록 복구 → 1분 휴식 시작 → 타이머 만료 시 `STOPPED(1)`·`active=false` → 평가 저장.

에뮬레이터는 호스트 오디오를 끈 상태로 실행했다. 네이티브 재생·제어 상태와 네트워크 음원 응답을 확인했으며 실차 스피커 음질·음압을 청취 검증한 것은 아니다.

## 1.2 두 모드 검증

- 구버전의 Guest 프로필과 공개 음악 목록을 유지해 1.2 APK로 업그레이드했다. 동승석 프로필은 동승자 모드로 복구됐다.
- 동승자 모드에서는 운전석이 나타나지 않고 운전자 모드에서는 운전석만 선택되는 것을 확인했다.
- 체험 어댑터를 주행 중으로 바꿨을 때 운전자 모드는 사용자가 주차 확인 버튼을 눌러도 시작하지 않았다. 같은 조건에서 동승자 음악·타이머는 시작됐다. 이 주행 조건은 실제 VHAL 주행 주입이 아닌 앱의 체험 어댑터 값이다.
- 실제 Audius 스트림을 시작한 뒤 다른 설정 앱을 열어 쉼, 자리가 숨겨져도 `PLAYING(3)`과 mediaPlayback FGS의 `isForeground=true`가 유지됐다.
- 시스템 미디어 제어의 일시정지에 `PAUSED(2)`로 응답하고 FGS가 해제됐다. 앱에서 다시 재생, 다음 곡의 메타데이터 변경을 확인했다.
- 프로세스 강제 종료·재실행 후 동승자 모드·타이머·목록을 복구했으며 사용자가 다시 재생하기 전에는 음악과 FGS가 자동 시작되지 않았다.
- 1분짜리 동승자 세션을 다른 앱이 열린 상태로 만료시켜 `STOPPED(1)`, 비활성 MediaSession, FGS 해제를 확인했다. 조용한 동승자 종료 채널과 앱 내 종료 화면을 확인했다.
- 최종 APK에서 운전자 모드의 주차 후 시작과 다른 앱으로 전환 시 음악 중지를 확인했다. 운전자 모드는 배경 음악 FGS를 만들지 않았다.
- 최종 APK에서 Activity 디스플레이 컨텍스트 변경 후 동승자 스트리밍을 다시 시작하고 다른 앱에서도 재생·FGS가 유지되는 것을 확인했다. 두 모드 세션 모두 종료·평가 후 정리했다.
- 테스트 자동화에서 발생한 창 전환 대기는 실제 포커스된 앱 창을 기다리도록 수정했다. 체험 어댑터의 주행 값은 프로세스 재생성 시 기본 주차 값으로 초기화되므로 테스트 전제와 구분했다.

최종 빌드는 Activity의 디스플레이 컨텍스트로 `CarUxRestrictions`를 조회하도록 했다. 상세 UI가 실제 승객 디스플레이와 주행 중 전환에서 적절히 제한되는지는 후속 검증 대상이다. 에뮬레이터는 호스트 오디오를 끈 상태이며 플레이어·서비스 상태를 확인했다.

## 1.3 연결·도착 전 기상 검증

추가 단위 테스트 21개로 도착 여유 시간·즉시 기상 ETA·이미 지난 예약·3시간 상한·자정·세션 복사·도착 기준 연장 제한·운전자 모드 분리·공용 선호·좌석 충돌·피드백·사설 주소 검증을 확인했다.

실행 검증은 공식 AOSP Android 15(API 35) x86_64 세로 휴대전화 에뮬레이터(1080×1920)에서 했다. 두 역할 모두 실제 릴리스 APK를 실행했다. 외부 TLS 기준 클라이언트/서버를 각각 연결해 구현 양쪽을 검증했으며, 두 APK를 서로 연결한 실차 시험으로 표현하지 않는다. 테스트 포트 전달과 기준 서버는 검사 전용이고 제출 APK에는 포함하지 않았다.

| 실제 APK 실행 항목 | 확인 결과 |
| --- | --- |
| 차량 역할 TLS 서버 | TLS 1.2 인증서와 암호화 프레임 교환 성공; Android Keystore의 TLS 서명 패딩 호환성을 수정한 뒤 재검사 |
| 연결 승인 | 잘못된 6자리 코드 거절, 차량 화면의 명시적 승인 뒤 토큰 발급 |
| 선호 전달 | 외부 클라이언트의 21.5°C·풍량 2·1분·선율 설정이 실제 APK 상태에 반영 |
| 음악 권한 | 대표가 아닌 동승자 요청 거절; 차량이 대표로 지정한 뒤 원격 재생으로 실제 MediaSession PLAYING 확인, 일시정지 요청 성공 |
| 복수 동승자 | 두 번째 동승자 승인, 중복 동승석 설정 거절 |
| 피드백 | 휴식 마치기와 추웠다는 평가 전송·상태 반환 성공 |
| 휴대폰 역할 TLS 클라이언트 | 실제 인증서 비교 화면, 연결 코드 입력, 암호화된 승인 토큰 수신과 상태 동기화 성공 |
| 도착 전 예약 | 차량 도착 5분 전 기상 선택, 로컬 PersonalWakeReceiver 알람 예약 확인 |
| 연결 해제 후 기상 | 연결 종료와 기준 서버 중단 후에도 개인 알림 ID 62 발생. 시스템에 무음·진동 패턴이 적용된 개인 기상 알림 기록 확인 |

진동 모터의 실제 체감, 실차 네트워크와 핫스폿 격리, 장시간 Doze, 재부팅·강제 중지는 검증하지 않았다. 알림과 정확한 알람 권한은 테스트 기기에서 허용했다. 같은 세션은 알림 발생 또는 명시적 해제 후 재예약하지 않도록 했다.

Pleos Connect 2.1.0 이미지에서는 OEM 네이티브 서비스의 반복 종료와 설치·UI 지연이 발생했다. 테스트 AVD의 재시작·초기화로도 안정적인 1.3의 두 기기 연속 검증을 완료하지 못했다. 내비게이션 어댑터는 공식 SDK와 타입·단위를 확인해 빌드했지만, 활성 경로의 ETA 수신·변경과 실차 공조 제어는 성공했다고 주장하지 않는다. 직접 입력 도착 시각과 정상 Android 환경에서의 연결 양쪽 검증을 구분한다.

## 1.3.1 이름·UI·시간 조절 검증

- 앱 표시 이름을 쉼, 자리로 변경하고 기존 패키지·서명으로 업데이트 설치했다.
- Pleos 공식 가이드에서 안내하는 Asta Sans와 중립 색상을 적용했다. 시스템 라이트·다크에 따라 앱과 연결 화면이 함께 바뀐다. 글꼴 라이선스를 APK에 포함했다.
- 360dp·411dp 세로 화면, 320dp와 글꼴 배율 1.3 조합, 960dp 가로 배치의 역할 선택·음악·프로필·설정·연결 화면을 확인했다. 가로 배치는 일반 Android 에뮬레이터의 해상도를 변경한 반응형 UI 시험이다.
- 동승자/운전자 버튼을 직접 선택해 모드 전환을 확인했다.
- 시간 −/+의 1분 단위 변경, 별도 15분·1시간 증감, 1분 하한·180분 상한을 실제 버튼 클릭으로 확인했다.
- 같은 위치에서 시간 증감 전후의 버튼 화면 좌표가 일치했다. 연결 화면의 개인 기상 예약 해제 버튼도 화면 위치를 유지했다.
- 기존 53개 단위 테스트 통과, Lint 오류 0·기존 경고 6개. 시간·차량·음악 정책은 기존 테스트 범위를 유지한다.

실행 화면과 색상·시간 조절 설명은 [UI 문서](UI.md)를 참고한다. 실차 연동에 대한 기존 미검증 항목은 그대로 남아 있다.

## 실제 Pleos 서비스 결과

Vehicle SDK 2.3.2를 통해 에뮬레이터 서비스의 capability 및 조회 콜백까지 연결했다. CAR_SPEED와 공조 권한을 허용한 상태에서도 선택 좌석의 온도 조회가 실패하거나 풍량 영역을 읽지 못하는 응답을 확인했다. 운전석·동승석에서 목표 설정을 지원하지 않는 것으로 처리했고, 적용 내역에는 현재 환경을 유지했다고 표시했다.

**실제 Pleos 공조의 쓰기·읽기 확인·복원 성공은 아직 검증하지 못했다.** 체험 모드에서 확인한 성공을 실제 차량 제어 성공으로 표시하지 않는다. 실제 온도·풍량 값과 capability를 제공하는 차량/버추얼 콘솔을 연결해 후속 검증해야 한다. P단·속도 변화와 실제 차량 동작을 함께 바꾸는 시험도 남아 있다.

## 남은 검증과 범위

- 실차, 실제 휴대전화 하드웨어, 다른 Pleos 서비스 버전 및 장시간 절전 상태의 알림은 미검증이다. Android 15 세로 휴대전화 에뮬레이터에서는 1.3 연결과 알림을 확인했다.
- 알림·정확한 알람 권한이 없으면 백그라운드 알림 또는 정확한 시각을 보장하지 않는다. 앱에서 해당 조건을 안내한다.
- 재부팅 후 자동 알람 재등록은 지원하지 않는다. 앱 재실행 시 저장한 종료 시각으로 복구한다.
- 1.2부터 동승자 음악은 배경에서 이어지며 운전자 음악은 화면 이탈 시 멈춘다. 실차 스피커 음질·음압·경고음과의 상호작용은 미검증이다.
- `CarUxRestrictions`의 초기 조회와 콜백 등록은 에뮬레이터에서 실행했다. 실제 차량의 주행 전환·승객 디스플레이·미디어 호스트 노출·스티어링 휠 키·Gleo 음성 제어와 앱 마켓 심사는 미검증이다. 동승자 역할 선택으로 주행 UI 허용을 보장하지 않는다.
- 좌석 자동 이동·습도 자동 제어·수면 단계 판정은 포함하지 않는다. NaviHelper ETA 어댑터는 구현했으나 실제 활성 경로에서의 수신 성공은 미검증이다.
- 기록은 주관적 휴식 느낌이다. 수면 개선 효능과 운전 재개 가능 여부를 판정하지 않는다.
